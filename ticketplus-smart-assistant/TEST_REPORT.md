## 開發過程中由測試發現並修正的問題

| # | 問題 | 修正 |
|---|---|---|
| 1 | 購票頁的注意事項「付款**逾時**將自動取消訂單」被誤判為「頁面逾時」 | 逾時／錯誤關鍵字只在標題、警示框、對話框中判斷（極短的錯誤頁才看全文） |
| 2 | 步驟列「1 選擇票券 2 確認訂單 3 結帳」可能讓選票頁被誤判為結帳頁 | 結帳關鍵字分為強／弱訊號；頁面上有可操作的張數控制時一律視為選票頁 |
| 3 | 全部售完的購票頁（沒有張數控制）被判為「無法辨識」 | 有價格的票種列多於場次列時視為購票頁 |
| 4 | 網路中斷時，頁面狀態的判斷覆蓋掉「網路中斷」提示 | 網路中斷的提示改為最後套用、優先顯示 |
| 5 | 區域「第一優先」留空時，第二優先會被往前移成第一優先 | 區域欄位保留固定三個位置 |
| 6 | 面板每 2 秒重繪，可能讓使用者正要按的按鈕被替換 | 內容沒有變化時不重繪，只更新偵測時間 |
| 7 | 面板中的文字（如「驗證碼」）可能被頁面辨識讀到而誤判 | 面板改掛在 `<body>` 之外並使用 Shadow DOM |

## 安全性驗證

- Enter 快速操作只呼叫 `focus()`，按鈕由使用者按 Enter 觸發（`isTrusted=true`）；付款類按鈕被排除，測試確認結帳頁的付款按鈕從未被選取。
- 模擬網站會記錄所有「非使用者觸發」（`isTrusted=false`）的點擊；在活動頁、購票頁（純監控與輔助模式）、驗證碼頁、結帳頁的測試中，外掛觸發的點擊次數皆為 **0**，「確認付款」按鈕從未被觸發。
- 原始碼檢查：外掛程式中沒有 `click()`、`submit()`、`fetch()`、`XMLHttpRequest` 或 `document.cookie` 的使用；唯一的合成事件是使用者確認後填寫欄位時送出的 `input`／`change`。
- Manifest 權限不含 `cookies`、`webRequest`、`declarativeNetRequest`、`scripting`、`debugger`、`<all_urls>`。
- 儲存層會拒絕任何名稱含 password／card／cvv／cookie／token 等字樣的欄位；購票資料只保留姓名、手機、Email。

## 已知限制

1. **未在正式 Ticket Plus 網站驗證。** 模擬網站依一般售票網站常見版面（場次列表、價格群組 + ＋／－ 按鈕、表格 + 下拉選單）製作；正式網站的實際文字與結構可能不同。辨識不到時外掛會顯示「無法辨識目前頁面」並停止，請先在開賣前打開活動頁確認。
2. 若官方使用第三方網域的排隊或付款頁面，外掛不會在該網域執行，只會顯示「目前頁面不在 Ticket Plus 官方網域」。
3. 桌面通知的實際彈出畫面無法在 headless 環境中目視確認；測試以「通知紀錄」與 Chrome API 的回傳結果驗證。音效需要作業系統未靜音。
4. 「外掛重新啟動」以呼叫復原流程的方式模擬（實際重新載入外掛會中斷測試連線）。
