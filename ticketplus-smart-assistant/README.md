# Ticket Plus Smart Ticket Assistant（Ticket Plus 購票小幫手）

專為台灣 **Ticket Plus 遠大售票系統** 設計的 Chrome 擴充功能（Manifest V3）。
它是一個**半自動購票輔助工具**，幫您：

- 預先設定購票條件（場次、票種、區域、張數），可保存多組活動設定
- 監控**您已開啟的**官方活動頁面票況，標示出符合條件的票券
- 開賣前提醒、偵測到符合條件的票券時立即發出桌面通知與音效
- 在您按下確認後，填寫姓名、手機、Email 等一般資料
- 出現驗證碼、排隊、簡訊驗證時立即暫停並通知您
- 進入訂單確認頁時停止一切操作，**由您親自確認訂單與付款**

> **外掛不會做的事**：破解驗證碼、繞過或改變排隊、呼叫未公開 API、偽造請求、讀取 Cookie、
> 使用多帳號／多視窗、點擊網站上的任何按鈕、送出訂單或付款。

## ⚖️ 使用前請先閱讀

1. **請詳閱 Ticket Plus 服務條款。** 若條款不允許使用輔助工具，請只使用「純監控模式」（預設），並以人工方式購票。
2. **法律提醒：** 依我國《文化創意產業發展法》相關規定，以虛偽資料或其他不正方法，利用電腦或其他相關設備購買藝文表演票券者可能觸法。本外掛刻意不自動點擊、不送出、不繞過任何檢查，但仍請您自行確認使用方式符合法規與平台規範。
3. **自動刷新預設關閉**，需要您閱讀說明並勾選同意後才能開啟，且最短間隔 30 秒。
4. 本外掛**尚未在正式的 Ticket Plus 網站上驗證過頁面辨識**（開發時刻意不對正式網站進行自動化測試）。頁面辨識採用不依賴網站程式結構的通用方式，若無法辨識，外掛會顯示「無法辨識目前頁面」並且不做任何動作。第一次使用時，建議在開賣前先打開活動頁面確認面板能正確顯示場次。

## 📦 安裝教學（不需要懂程式）

1. 下載本專案，取得 `ticketplus-smart-assistant` 資料夾（如果下載的是 ZIP 檔，請先解壓縮）。
2. 打開 Google Chrome（需 120 版以上），在網址列輸入 `chrome://extensions` 並按 Enter。
3. 打開右上角的 **「開發人員模式」** 開關。
4. 按左上角的 **「載入未封裝項目」**，選擇 `ticketplus-smart-assistant` 資料夾（裡面要直接看得到 `manifest.json`）。
5. 安裝完成後會自動開啟「使用須知」，閱讀後勾選同意。
6. 建議按瀏覽器右上角的拼圖圖示 🧩，把「Ticket Plus 購票小幫手」**釘選**到工具列。
7. 請確認電腦允許 Chrome 顯示通知：
   - **Windows**：設定 → 系統 → 通知 → 開啟 Google Chrome
   - **macOS**：系統設定 → 通知 → Google Chrome → 允許通知
8. 在設定頁按「🔔 測試通知」，看到通知並聽到提示音就代表設定完成。

## 🧭 操作教學

### 1. 建立活動設定
點外掛圖示 → 「⚙ 編輯購票設定」→「＋ 新增活動設定」，依序填寫：

| 欄位 | 說明 | 範例 |
|---|---|---|
| 活動名稱 | 自己看得懂的名稱 | 演唱會 A 台北場 |
| 活動網址 | 在官網打開活動頁後複製網址 | `https://ticketplus.com.tw/activity/…` |
| 開賣日期／時間 | 用來倒數與提醒 | 2026-12-01 12:00 |
| 預計購票場次 | 場次日期或地點中的文字，多個用逗號 | `12/20` |
| 優先票種／備選票種 | 多個用逗號，越前面越優先 | `全票`／`身障票` |
| 第一～第三優先區域 | 請照官方頁面上的寫法 | `VIP A區`、`A1區` |
| 購買張數 | 實際上限以官方頁面為準 | 2 |
| 提示其他區域 | 偏好區域沒票時，列出其他有票區域供您參考（不會替您選） | |

按「💾 儲存設定」。可建立多組（演唱會 A、B、C），用「⭐ 設為目前使用」切換。

### 2. 選擇運作模式
- **純監控模式（預設、建議）**：只讀取頁面、標示符合的票券並通知，不修改任何欄位。
- **輔助模式**：額外提供「✍ 填寫購票資料」與「設定張數（僅限下拉選單）」按鈕；每個動作都會先顯示預覽，**經您按「確認執行」才會進行**。網站使用「＋／－」按鈕選張數時，外掛只會提示您自己按。

### 3.（選用）填寫購票資料
設定頁 →「👤 購票資料」：填姓名、手機、Email，勾選「同意儲存在本機」後儲存。
外掛**絕不儲存**密碼、信用卡號、安全碼、驗證碼、Cookie 或身分驗證憑證。

### 4. 開賣當天
1. 先在 Ticket Plus 官網**自行登入**會員。
2. 打開活動頁面，點外掛圖示 →「▶ 開始監控」。頁面右下角會出現藍色狀態面板（可按「－」縮小）。
3. 開賣前 N 分鐘會收到提醒（可在設定中調整）。
4. 偵測到符合條件的場次／票券時：桌面通知 + 音效 + 頁面上以**藍色框**標示，面板依優先順序列出，按「📍 定位」可捲動到該位置。**請您親自點擊網站上的按鈕。**
   **⌨ Enter 快速操作**（預設開啟，可在活動設定中關閉）：外掛會把活動頁切到最前面，並用**橘色框選取**要按的按鈕，您只要按 Enter：
   - 活動頁：選取符合場次的「立即購買」→ 按 Enter 進入購買；
   - 購票頁：選取最優先票種的「＋」→ 要幾張就按幾次 Enter。選滿設定張數時會**立刻放開選取**，多按也不會多選；若網站用下拉選單，直接按數字鍵即可；
   - 您點了其他欄位後外掛不會把焦點搶回來，需要時按面板上的「⌨ 選取按鈕」；
   - 外掛只「選取」按鈕，按下 Enter 的是您本人；付款、結帳、送出類按鈕**永遠不會**被選取。
5. 出現**驗證碼、簡訊驗證、排隊頁面或登入頁**：外掛立即暫停並通知，請親自完成；排隊時請勿重新整理。
   出現驗證碼或簡訊驗證時，為了讓您**最快開始輸入**，外掛會：
   - 自動把活動分頁與 Chrome 視窗切到最前面；
   - 捲動到驗證碼位置，並把**游標放進驗證碼輸入框**，您直接打字即可（若您正在其他欄位打字，則不會搶走游標）；
   - **重複響提示音**（約每 4 秒一次，最多約 1 分鐘），您一按鍵盤或滑鼠就停止。
   驗證碼的內容一律由您自己看、自己輸入，外掛不會讀取或填寫。
6. 進入**訂單確認／付款頁**：外掛停止一切操作，面板列出您的設定與網站顯示的訂單資訊，請逐項核對後**親自完成付款**。

### 主畫面按鈕
| 按鈕 | 作用 |
|---|---|
| ▶ 開始監控／繼續監控 | 綁定目前的活動分頁開始監控（找不到時會開啟活動網址） |
| ⏸ 暫停監控 | 暫停通知與刷新，面板仍顯示狀態 |
| ⏹ 停止監控 | 結束監控並移除頁面上的面板 |
| 🔗 開啟活動頁面 | 開啟或切換到活動頁面（不會重複開啟） |
| ⚙ 編輯購票設定 | 開啟設定頁 |
| 📋 監控紀錄 | 查看時間、偵測狀態、票券資訊、通知、操作結果與錯誤 |

### 自動刷新（選用）
在「監控與通知設定」中開啟，必須勾選「我已了解並會遵守售票網站規範」。
- 只有頁面顯示「尚未開賣」或「已售完」時才刷新；**排隊、驗證碼、登入、選票、結帳頁面永不刷新**。
- 最短 30 秒；您正在操作頁面（20 秒內有點擊或打字）時會跳過。
- 若售票網站禁止自動刷新，請保持關閉，外掛仍會監控您已開啟的頁面內容。

## 🛠 常見錯誤排除

| 狀況 | 可能原因與解決方式 |
|---|---|
| 頁面上沒有出現面板 | ① 尚未按「開始監控」② 外掛只在 `https://ticketplus.com.tw` 運作 ③ 安裝／更新外掛前已開啟的頁面需重新整理一次 |
| 面板顯示「無法辨識目前頁面」 | 網站可能改版或頁面尚未載入完成。外掛不會做任何操作，請手動購票，並回報給開發者更新 `ticketplus-adapter.js` |
| 面板一直顯示「頁面載入中」 | 等待最多 15 秒；若網路緩慢請手動重新整理 |
| 沒有收到桌面通知 | 檢查作業系統的通知權限、Chrome 是否開啟「專注模式／勿擾模式」，並在設定頁按「測試通知」。也請確認活動設定中的「Chrome 桌面通知」有勾選 |
| 驗證碼出現時游標沒有自動放進輸入框 | 頁面上若有多個可能的輸入框、驗證元件在 iframe 內（例如 reCAPTCHA），或您已經在其他欄位打字，外掛只會捲動到驗證位置，請直接點選輸入框 |
| 驗證碼提示音一直響 | 在頁面上按任一鍵或點一下滑鼠就會停止；也可在活動設定中關閉「通知音效」 |
| 按 Enter 沒有反應 | 確認 Chrome 視窗在最前面、按鈕上有橘色框；若您點過其他地方，請按面板上的「⌨ 選取按鈕」再按 Enter |
| 沒有聲音 | 確認活動設定中「通知音效」有勾選，電腦未靜音 |
| 找不到符合的票券，但頁面上有票 | 票種、區域名稱需與官方頁面上的文字相符（例如「VIP A區」vs「VIPA區」可能不同）；張數超過剩餘數量或限購張數時也不會列為符合 |
| 「填寫購票資料」按鈕沒有出現或是灰色 | 需為「輔助模式」、監控中，且不在驗證／排隊／結帳頁 |
| 填寫時顯示「找到多個疑似欄位」 | 為避免填錯，外掛不會猜測，請手動填寫 |
| 關閉活動頁後監控變成「已暫停」 | 正常的保護機制；重新開啟活動頁後按「繼續監控」 |
| 重新啟動 Chrome 後監控暫停 | 找不到原本的分頁時會安全暫停，請重新開啟活動頁並繼續監控 |
| 出現「網路中斷」 | 恢復連線後外掛會自動重新偵測，請確認頁面內容是否仍正確 |
| 想刪除所有資料 | 設定頁 →「🗑 資料管理」→「清除所有資料」 |
| 載入外掛時出現檔案名稱錯誤 | 請勿在外掛資料夾內執行 `npm install`（`node_modules` 會導致 Chrome 無法載入），刪除該資料夾後重新載入 |

## 🗂 專案結構

```
ticketplus-smart-assistant/
├── manifest.json            Manifest V3 設定（權限最小化：storage、notifications、alarms、tabs、offscreen）
├── config.js                共用常數與安全政策（POLICY）
├── storage.js               chrome.storage.local 封裝、資料驗證、敏感欄位阻擋
├── notification.js          桌面通知、音效、防重複通知
├── offscreen.html / .js     播放提示音（MV3 service worker 無法直接播放聲音）
├── background.js            Service worker：監控狀態、通知判斷、鬧鐘、分頁事件、重新啟動復原
├── ticketplus-adapter.js    Ticket Plus 頁面辨識模組（網站改版時只需改這裡）
├── content.js               內容腳本：讀取票況、狀態面板、使用者觸發的輔助動作、人工確認
├── popup.html / .css / .js  外掛主畫面
├── options.html / .css / .js 設定頁（活動設定、購票資料、監控紀錄、使用說明、資料管理）
├── icons/                   16／48／128 圖示
├── tests/                   測試環境（模擬售票網站 + 自動化測試）
├── TEST_REPORT.md           測試報告
└── README.md
```

### 架構與安全設計
- **單一分頁監控**：一次只綁定一個分頁，不開多視窗或多工作階段。
- **不發網路請求**：內容腳本只讀取畫面上已顯示的內容（MutationObserver + 每 2 秒重新評估）；唯一會讓頁面重新載入的是「使用者同意後的低頻率刷新」，使用一般的瀏覽器重新整理。
- **永不點擊**：`config.js` 的 `POLICY.AUTO_CLICK_SITE_BUTTONS = false`；程式中沒有任何對網站元素呼叫 `click()` 的程式碼。測試中的模擬網站會記錄所有「非使用者觸發」的點擊，測試確認次數為 0。
- **安全檢查優先**：Adapter 的判斷順序為 驗證元件 → 簡訊／身分驗證 → 驗證碼 → 排隊 → 登入 → 逾時／錯誤 → 結帳 → 選票 → 活動頁，任何一項成立就停止輔助。
- **不確定就停止**：無法辨識時回傳 `unknown`，外掛不做任何動作。
- **面板隔離**：狀態面板使用 Shadow DOM，並掛在 `<body>` 之外，不影響網站樣式，也不會被頁面辨識讀到。

### 網站改版時如何更新（給開發者）
`ticketplus-adapter.js` 中的 `KEYWORDS`（狀態文字）與 `URL_HINTS`（網址特徵）是主要調整點。
辨識演算法不依賴 CSS class：先找出畫面上的狀態文字或張數控制元件，再往上找出「與兄弟元素結構相同」的列（row）。
修改後請執行測試，並在 `tests/mock-site/` 新增對應新版面的模擬頁面。
